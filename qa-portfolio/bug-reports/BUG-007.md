# BUG-007 — Add-product DB errors never shown (`$err_msg` vs `$error_msg`)

| Field | Value |
|-------|--------|
| Severity | **Medium** |
| Priority | Medium |
| Status | Open |
| Environment | Code review + local admin add form |
| Module | Menu admin |
| Related case | MENU-16 |

## Summary

On add failure from the `Mancare` class, the script sets `$err_msg`, but the template prints `$error_msg`. Admins see a silent failure/empty alert region.

## Steps to reproduce

1. Review `src/add.php`: success path vs error assignment vs template.
2. Force `$mancare->error` after `add()` (e.g. DB issue).

## Expected

Danger alert shows the class error string.

## Actual

Variable name mismatch → alert block empty / undefined variable behavior depending on PHP notices settings.

## Notes / root cause hint

```php
$err_msg = $mancare->error;   // assignment
// template:
<?php if (!empty($error_msg)){ ?>
```
