# BUG-009 — Add product form reflects HTML / script without escaping

| | |
|--|--|
| Severity | High |
| Priority | High |
| Status | Open |
| Build | Local, http://127.0.0.1:8080/add.php |
| Area | Menu admin |
| Case | MENU-17 |

## Summary

On Add product, if validation fails (I used a bad price), the name and description are put back into the inputs without escaping. I could break out of the attribute with a payload.

## Steps

1. Log in as admin.
2. Open Add product.
3. Name: `"><img src=x onerror=alert(1)>`
4. Description: `"><svg/onload=alert(2)>`
5. Price: `-5` (so the form fails).
6. Submit.
7. Inspect the name / description fields in the page source.

## Expected

Escaped value, no extra tags in the markup.

## Actual

Something like:

```html
value=""><img src=x onerror=alert(1)>"
```

Same idea on the description field with the SVG payload.
