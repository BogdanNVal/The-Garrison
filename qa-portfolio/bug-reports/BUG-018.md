# BUG-018 — Logout works with a plain GET (no confirm / no token)

| | |
|--|--|
| Severity | Medium |
| Priority | Medium |
| Status | Open |
| Build | Local |
| Area | Security |
| Case | AUTH-22 |

## Summary

`/logout.php` logs you out on a normal GET. While I was logged in, hitting that URL cleared the session (and remember cookie). There’s also no CSRF-style token on the admin add/update/delete forms — just a normal POST.

## Steps

1. Log in as customer (or admin).
2. Open `/logout.php` in the same browser (or imagine another site loading that URL).
3. Try a protected page (e.g. `/rezervare.php`).

## Expected

Logout needs a deliberate user action (e.g. POST + token). Admin changes shouldn’t be forgeable from another site while you’re logged in.

## Actual

GET logout sends you to login and you’re out. Delete/add forms don’t carry any extra token field.

## Notes

Logged as one finding: easy logout via GET, and mutating admin forms with nothing CSRF-like on them.
