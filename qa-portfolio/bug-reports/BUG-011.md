# BUG-011 — Non-numeric price is accepted and stored as 0 (or truncated)

| | |
|--|--|
| Severity | High |
| Priority | High |
| Status | Open |
| Build | Current main, http://127.0.0.1:8080 |
| Area | Menu admin |
| Cases | MENU-07, MENU-08 (related) |

## Summary

`add.php` / `update.php` only reject prices with `$pret <= 0`. A non-numeric string like `abc` does **not** satisfy that check in PHP 8, so validation passes. `bind_param("d", …)` then coerces the value to `0.0`, and the product is saved.

`12abc` was stored as `12.00` (numeric prefix kept).

This reopens the spirit of BUG-003 (zero price in DB) through a different input.

## Steps

1. Log in as admin.
2. POST Add product with name/description/image valid, price `abc` (or use the form and bypass `type=number` via curl/devtools).
3. Check `meniu` / admin list.

## Expected

Validation error; item not created.

## Actual

Redirect to admin panel. DB row:

```
AbcPrice     0.00
TwelveAbc   12.00   (from pret=12abc)
```

## Notes

Same `$pret <= 0` pattern on `update.php`. Need `is_numeric` / `filter_var(..., FILTER_VALIDATE_FLOAT)` and require `> 0` after cast.
