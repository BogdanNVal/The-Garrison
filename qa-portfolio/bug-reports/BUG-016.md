# BUG-016 — Party size accepts non-integers (`2.5`, `2abc`)

| | |
|--|--|
| Severity | Medium |
| Priority | Medium |
| Status | Open |
| Build | Current main, `/rezervare.php` |
| Area | Reservations |

## Summary

Server checks `$nr_persoane <= 0` and `> 6` on the raw string from the request. Values like `2.5` and `2abc` pass those checks under PHP’s type juggling, the booking succeeds, and the DB stores a coerced integer (`2`). HTML `min`/`max` on the number input is easy to bypass with curl.

Insert also uses `bind_param("ssdd", …)` for integer columns `nr_persoane` / `id_masa` (should be `"ssii"`).

## Steps

1. Log in as customer.
2. `curl` POST to `/rezervare.php` with `nr_persoane=2.5` and a future date (and again with `2abc`).
3. Check `rezervari`.

## Expected

Reject non-integer / out-of-range party size with a clear error; no row.

## Actual

HTTP 302 to home. Rows created with `nr_persoane=2` for both `2.5` and `2abc` payloads.

## Notes

Use `ctype_digit` or cast + strict range `1..6` after validating the string is an integer.
