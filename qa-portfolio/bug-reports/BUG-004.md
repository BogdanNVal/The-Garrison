# BUG-004 — Signup name field reflects HTML / script

| | |
|--|--|
| Severity | High |
| Priority | High |
| Status | **Fixed** (retested on current main) |
| Build | Current main, /signup.php |
| Area | Auth |
| Case | AUTH-19 |

## Summary (original)

If signup failed validation, the name was put back into the input without escaping, so a payload could break out of the attribute.

## Retest on current main

1. Open Sign up.
2. Name: `"><img src=x onerror=alert(1)>`
3. Email: `x` (invalid).
4. Submit and inspect the name field in the page source.

## Expected

Escaped value, no extra tags in the markup.

## Actual (now)

Value is HTML-escaped, e.g. `value="&quot;&gt;&lt;img src=x onerror=alert(1)&gt;"`.

## Notes

Signup uses `htmlspecialchars` on re-displayed fields. Related open issue on the **add** form: see BUG-009.
