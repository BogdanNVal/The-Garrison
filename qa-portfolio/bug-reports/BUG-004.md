# BUG-004 — Signup name field reflects HTML / script

| | |
|--|--|
| Severity | High |
| Priority | High |
| Status | Open |
| Build | Local, /signup.php |
| Area | Auth |
| Case | AUTH (validation / escaping) |

## Summary

If signup fails validation, the name is put back into the input without escaping. I could break out of the attribute with a payload.

## Steps

1. Open Sign up.
2. Name: `"><img src=x onerror=alert(1)>`
3. Email: `x` (invalid, so the form fails).
4. Submit.
5. Inspect the name field in the page source.

## Expected

Escaped value, no extra tags in the markup.

## Actual

Something like:

```html
value=""><img src=x onerror=alert(1)>"
```

![xss on signup](../docs/screenshots/BUG-evidence-xss.png)

## Notes

Name is echoed raw into `value="..."`. Easy to miss if you only test happy path.
