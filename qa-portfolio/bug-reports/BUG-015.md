# BUG-015 — Remember-me cookie is not HttpOnly; DB token survives “no remember” login

| | |
|--|--|
| Severity | High |
| Priority | High |
| Status | Open |
| Build | Current main, `/login.php` |
| Area | Auth / cookies |

## Summary

Two related remember-me issues:

1. `setcookie("remember_token", …)` is called **without** `HttpOnly` (also no `Secure` / `SameSite`). Any XSS in the admin UI (e.g. BUG-012) can steal the 1-year token.
2. Logging in **without** Remember me only expires the browser cookie. It does **not** clear `remember_token` in `admins` / `users`. A previously issued token still works if the attacker kept a copy.

## Steps

### A — Cookie flags

1. Log in with Remember me checked.
2. Inspect `Set-Cookie: remember_token=…`.

### B — Stale DB token

1. Log in with Remember me; copy the cookie value; note DB hash is set.
2. Log in again **without** Remember me (response clears cookie).
3. Confirm DB `remember_token` is still non-empty.
4. Send a request with only the old `remember_token` cookie (no session) to `/secure.php` or `/index.php`.

## Expected

HttpOnly cookie; logging in without Remember me clears the stored hash; stolen old cookie must not restore the session.

## Actual

- Cookie: `path=/`, long Max-Age, **no HttpOnly**.
- After no-remember login: DB token unchanged; stolen cookie still authorized admin (`/secure.php` → 200).

## Notes

Admin and customer share the same cookie name (`remember_token`), so only one role can be “remembered” per browser.
