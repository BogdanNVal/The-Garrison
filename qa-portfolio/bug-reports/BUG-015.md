# BUG-015 — Remember me cookie is easy to steal / old token still works

| | |
|--|--|
| Severity | High |
| Priority | High |
| Status | Open |
| Build | Local, /login.php |
| Area | Auth |
| Cases | AUTH-20, AUTH-21 |

## Summary

Two things with Remember me:

1. The `remember_token` cookie is readable from JavaScript (no HttpOnly). With the Update XSS (BUG-012) that matters.
2. If I log in with Remember me, then later log in again **without** the checkbox, the browser cookie is cleared but the token in the database is still there. Replaying the old cookie still got me into the admin panel.

## Steps

1. Log in as admin with Remember me on. Copy the `remember_token` cookie from DevTools.
2. Check that the cookie flags don’t include HttpOnly.
3. Log out / log in again **without** Remember me.
4. From a “fresh” browser state, send a request with only that old `remember_token` cookie to `/secure.php`.

## Expected

Cookie not readable by scripts. Logging in without Remember me should invalidate the old token. Stolen cookie shouldn’t reopen admin.

## Actual

Cookie has a long expiry and no HttpOnly. After a no-remember login, the DB token was still set, and the old cookie still opened `/secure.php`.

## Notes

Admin and customer seem to share the same cookie name, so only one “remembered” role per browser.
