# BUG-012 — Update product page runs HTML from the dish name

| | |
|--|--|
| Severity | High |
| Priority | High |
| Status | Open |
| Build | Local, /update.php |
| Area | Menu admin |
| Case | MENU-19 |

## Summary

I added a dish whose name was an HTML/script payload (valid price + image). Public menu looked fine. Opening **Update** for that dish broke the name field — the markup escaped the attribute and the image/onerror showed up in the page.

## Steps

1. Log in as admin.
2. Add a product with name `"><img src=x onerror=alert(11)>`, price `11.11`, normal description, valid PNG.
3. From the admin menu, open Update on that product.
4. Inspect the name field in the page source (or just look at the broken layout).

## Expected

Name shown safely in the input, no extra tags in the markup.

## Actual

Something like:

```html
value=""><img src=x onerror=alert(11)>"
```

## Notes

Same kind of issue as BUG-009 on Add, but here the bad value is already stored and comes back when you edit. Public list / home menu didn’t show the breakout.
